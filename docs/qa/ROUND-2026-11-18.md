# Cresavo concept demo: QA and regression round

**Date:** 18 November 2026
**Build:** commit `e193bd4`, detached worktree, built as in production (`vercel.json` env, `next build`, Next 16.4.6 Turbopack), served by `scripts/server.mjs` on port 3100 with `PUBLIC_READONLY=1` and `BOOKING_RUNTIME=local`.
**Hosts:** `cresavo.com`, `www.cresavo.com`, `demo.cresavo.com`, `salong-eko.cresavo.com`, `annas-fotvard.cresavo.com`, `boka.salong-eko.example` and an unknown host. Chromium resolved them all to 127.0.0.1 with `--host-resolver-rules`.
**Browser:** the preinstalled Chromium 1243, because the repo's Playwright 1.65 expects a browser build that is not installed. The mapped http origins were treated as secure contexts (see "Test-environment notes").
**Exploratory pass:** OpenAI Codex CLI 0.169.0, `codex exec -m gpt-6.2-sol --sandbox workspace-write -c sandbox_workspace_write.network_access=true`. It ran for about 45 minutes and used 284k tokens.

## Summary

The automated regression is mostly green. I found no broken internal links, no hydration warnings and no axe-core violations on 31 pages in 3 modes. Back/forward, deep links, the 390 px tab bar, the 1280 px sidebar and dark mode all work. The core flows pass: booking a caller, move, cancel and undo, mark done, presets, waitlist and public booking.

The real problems are in the journeys around those flows. I confirmed **22 findings** by reproducing each one in a clean browser context with `qa/verify-findings.mjs`. Codex found 15 and all 15 reproduced. I found 7.

**Most important:**

1. **On the local production build, the "Explore the demo" button on cresavo.com sends visitors back to the coming-soon page.** The same build also sends `X-Robots-Tag: noindex` on that page, which is the one page meant to be indexed. Both appear to come from one cause: after the host rewrite, the page and the header logic see an internal host (`localhost:3100`) instead of `cresavo.com`. Check this on Vercel first: `curl -sI https://cresavo.com/ | grep -i robots`, and look at the "Explore the demo" href.
2. **A first-time caller cannot be booked from "Someone is calling".** Neither the caller sheet nor the New booking form has a way to add a customer, so the main phone flow stops for new customers.
3. **A 45-minute gap opens New booking with a 60-minute treatment selected.** The form lets you press Book, then says "That time is no longer free", and that message is hidden behind the sheet.
4. **Several places disagree with each other.** The Morning brief still says a slot is free after it is booked. The room filter shows "0 bookings" under "81% booked". The booking search says "three times" and shows two. Reschedule accepts the same time and says "moved".
5. **The assistant answers "I did not understand" to 3 of 10 everyday questions**: availability, low stock and opening hours. Its own fallback text says it can look up free times and stock.
6. **Some demo state is lost or never shows up.** With two tabs open, the second booking overwrites the first. A booking made on the salon subdomain never reaches the studio, even though the confirmation says it is "saved in the owner's Inbox".

## Confirmed findings

"C" findings came from Codex and "O" findings from my pass. I re-ran every one with `node --import tsx qa/verify-findings.mjs`. The results are in `qa/out/verify-findings.json` and the screenshots in `qa/out/shots/verify-*.png`. Codex screenshots are in `codex/shots/`.

### High

**H1 (C03): "Explore the demo" on cresavo.com loops back to the coming-soon page.**
Steps: open `https://cresavo.com/` at any width and click **Explore the demo**.
Expected: the demo landing (`https://demo.cresavo.com/`) opens. Actual: the server renders `href="/"`, and on the apex host `/` is the coming-soon page again.
Cause: `getSiteProps` reads `req.headers.host`. After the proxy's `NextResponse.rewrite`, that host is `localhost:3100` (see `x-middleware-rewrite: http://localhost:3100/coming-soon`), so `siteLinks()` treats the request as "app" and returns relative links. This reproduces under both `scripts/server.mjs` and `next start`. I could not check Vercel because I had no web access.
Screenshots: `verify-C03-after-explore.png`, `codex/shots/apex-after-explore-390.png`, `codex/shots/F01-apex-demo-link-1280.png`.

**H2 (C04): A first-time caller cannot be booked from "Someone is calling".**
Steps: on `/studio`, click **Someone is calling**, search "QA New Customer", then tap a free time.
Expected: the owner can enter the new caller's name and number and book. Actual: neither sheet has an add-customer action. The New booking form says "No customer matches." and Book stays disabled.
Screenshots: `verify-C04-new-caller.png`, `codex/shots/caller-unknown-wizard-390.png`.

## Not reproducible or not a defect

| Observation | Verdict |
|---|---|
| `/studio/more/staff` → `GET /api/concept/calendar` 403 (first crawl) | **Test artifact.** Over plain `http://demo.cresavo.com` Chrome sends no `Sec-Fetch-Site`, and `fromSameOrigin()` then compares Origin with an internal URL. With the origins treated as secure (like production https) it answers 200. Codex's runs used plain http and headless-shell, so any 403 it saw comes from the same artifact. |
| Booking page stays light in dark mode | **By design.** Salong Eko's page theme is light, and the neutral default follows the OS. `tests/concept-e2e/theme.spec.ts` pins this. |
| Language switch "missing" on studio, booking page, landing and coming soon | **By design.** The concept UI is English-only. See L9 for the side effect. |
| Codex: desktop drag in the calendar "inconclusive" | Not a finding. Headless pointer drag does not emit native DnD events. A synthetic drop and the Move action both worked. |
| `requestfailed POST /api/locale net::ERR_ABORTED` and `GET /api/concept/ai ERR_ABORTED` | Cancelled by navigation or `router.refresh()`. Harmless. |
| Download link `/demo/customers-example.csv` "fails" in the crawler | It is a download, which works. |
| axe colour-contrast "incomplete" (535 nodes) | Undeterminable backgrounds, not failures. The tint scan found no low-contrast same-hue text. |

## Test-environment notes

- The repo's `playwright` 1.65 wants `chromium_headless_shell-1254`, but this image has 1243. The scripts fall back to `/opt/pw-browsers/chromium-*/chrome-linux64/chrome`. In CI, `npx playwright install chromium` removes the need for this.
- `--unsafely-treat-insecure-origin-as-secure` is set for the mapped hosts so that `Sec-Fetch-*`, the clipboard and other secure-context behaviour match https production. The headless shell ignores this flag, which is why the scripts use full Chromium.
- `codex exec` waits on stdin when it is started in the background, so run it with `< /dev/null`. With `--sandbox workspace-write -c sandbox_workspace_write.network_access=true` it reached `127.0.0.1:3100` and could run Node and Chromium on the first try.
- The demo keeps all state in each browser's localStorage (`salong-eko-demo`), and the state is only written on the first change. `flows.mjs` seeds the same state through `createDemoState()`, which is why it runs with `--import tsx`.
