# Cresavo 0.8.0 – customer data rights, safer sign-in and the groundwork for a pilot

> Pre-release. Concept demo with fictional data; not ready for real customers yet.

0.7.0 made online booking work. 0.8.0 covers what a salon needs before it can trust Cresavo with real people: customers can see, correct and remove what is stored about them, and owners get a safer sign-in. There are also the routines to run the service: backups, an incident plan and tight database permissions. Owner sign-in and live booking stay switched off in the public demo until the last checks are done.

## New since 0.7.0

- **Every customer's data, in one place.** On a customer's page, "Their data" downloads everything the salon holds about them as a file or a spreadsheet: visits, notes, messages, consents and purchases, and nothing about anyone else. Every detail can be corrected there. A customer can also be erased for good, with a clear note on what is kept for bookkeeping.
- **Old data does not pile up.** Customers who have not visited for three years are listed for review; nothing is deleted without the owner's choice. Message texts, the activity history and old sign-in counters are cleared on a schedule. Under More, Privacy shows who read a journal and when, never what it says.
- **Safer owner sign-in.** An account locks for a while after repeated wrong passwords. A forgotten password can be reset from a link that works once and expires after 30 minutes. Sessions end after a period of inactivity, and "Sign out everywhere" ends them on every device.
- **What's new, inside the studio.** Help now has a "What's new" list. A small dot on the Help button shows when there is something you have not seen yet.
- **Easier to use with a screen reader.** Every main page of the site, the booking flow and the studio is checked automatically for accessibility in light and dark mode, on phone and desktop. On phones, side panels no longer announce a second page heading area.
- **Protection against misuse.** Every public address that saves something, sends an e-mail or costs money now limits how often one visitor can call it. Tests also try to read and change one salon's data while signed in as another salon, and every attempt is refused.
- **Ready to run.** There is a backup and restore drill, an incident runbook and database roles that give each part of the service only the access it needs.

## What is still needed before real salons go live

- Two-step sign-in for owners, and database-level separation between salons.
- An e-mail provider, a production database with backups, and monitoring.
- A legal review of the data processing agreement, the impact assessment for journals and the retention periods.
- An independent security review. See the [pilot gate](https://github.com/Cresavo/cresavo/blob/main/docs/QUALITY_SECURITY.md).

## Try it

- In the browser: [demo.cresavo.com](https://demo.cresavo.com). Open a customer to see "Their data", and Help → What's new.
- On your machine (Node.js 22.12+):

```bash
git clone https://github.com/Cresavo/cresavo.git
cd cresavo
npm run demo
```
